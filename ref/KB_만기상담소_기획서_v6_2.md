# 0. 처음 보는 사람을 위한 3분 요약

**문제:** 임차인은 계약 만기(주택임대차보호법상 최소 보장 2년, 월세는 1년 계약도 흔함)를 주기적으로 맞는다. 전세든 월세든 그 순간 세 갈래 앞에 선다 — ① 갱신(눌러앉기) ② 이사(옮기기) ③ 매매(사기). 각각 보증금·대출·월 부담이 완전히 다른데, **셋을 한 화면에서 비교해주는 곳이 세상에 없다.** 부동산 앱은 매물만 보여주고, 은행 앱은 상품별 한도만 보여준다. 결국 사람들은 감으로 결정하거나, 미루다가 갱신 통보 기한을 놓친다.

**해결:** 만기일을 입력하면(또는 감지하면) AI 에이전트가 ① 갱신 시 예상 비용 ② 지금 보증금으로 옮길 수 있는 동네 ③ 보증금+대출로 살 수 있는 집을 **하나의 비교표**로 계산하고 — **각 갈래의 리스크(보증금 반환 위험 등)와 대비 수단(반환보증 보증료)까지 월 부담으로 환산해 같은 저울에 올린다.** 이사·매매 경로는 **"그 동네에서의 하루" 숏폼**으로 체감시키고, 선택한 경로의 KB 상품(대출+보장 패키지)으로 연결한다.

**왜 신박한가:** "주거 상담"이 아니라 **"만기"라는 순간을 잡았다.** 만성적 고민(언젠가 집)이 아니라 데드라인이 달력에 박힌 급성 결정이다. 그리고 세 갈래를 동시에 놓고 비교하는 서비스는 부동산 앱도 은행 앱도 만든 적 없다.

**왜 은행만 가능한가:** 세 갈래의 비교 변수가 전부 금융이다 — 갱신=전세대출 연장/증액, 이사=신규 전세대출, 매매=주택담보대출. 대출 없이 이 비교는 성립하지 않는다.

**왜 KB에 돈이 되는가:** 만기 시점은 전세대출이 타행으로 이탈하거나, 전세→매매 전환으로 주담대가 발생하는 **여신의 분기점**이다. 그 순간을 D-90부터 선점한다.

**안전한가:** 산출물은 "판단"이 아니라 **"비교표와 시뮬레이션"**이다. 모든 숫자는 코드가 공개 룰·공개 데이터로 계산하고, 결정은 사용자가 한다. 예측 없음, 권유 없음.

# 1. 문제 배경

## 1-1. 계약 만기마다 돌아오는 시험

대한민국 임차 가구는 수백만이고, **전세든 월세든** 이들 전원에게 **계약 만기**가 주기적으로 돌아온다.
(주택임대차보호법상 최소 보장기간 2년과 계약갱신요구권·인상률 상한은 **전월세 공통** 적용 — 월세는 1년 계약도 흔해 만기가 더 자주 온다.)
그리고 만기 앞에서 모두가 같은 세 갈래를 마주한다.

```
        🏠 눌러앉기 (갱신)          🚚 옮기기 (이사)           🔑 사기 (매매)
   ─────────────────────    ─────────────────────    ─────────────────────
   갱신청구권 쓸 수 있나?      지금 보증금으로 어디 가지?    이 돈에 대출 껴서 될까?
   5% 올려주면 얼마지?        이사비·중개비까지 얼마지?     월 상환이 월세보다 낫나?
   보증금 더 달라면?          새 동네는 살만한가?          평생 최대 결정인데...
```

**세 질문의 답은 서로 연결되어 있는데, 답을 주는 곳은 다 흩어져 있다.**
- 갱신 룰(계약갱신요구권·인상률 상한) → 법령·블로그 검색
- 이사 갈 동네 시세 → 부동산 앱
- 매매 가능 여부 → 은행 대출 상담 (문턱 높음)

그래서 대부분은 **비교 없이 관성으로 갱신하거나, 감으로 결정하거나, 미루다 통보 기한을 놓친다.**

## 1-2. 이 비교를 완성할 수 있는 곳은 은행뿐이다

세 갈래의 공통 변수 = **대출.**

| 갈래 | 핵심 금융 변수 |
|---|---|
| 눌러앉기 | 전세대출 **연장·증액** 가능액과 이자 |
| 옮기기 | 신규 **전세대출** 한도 |
| 사기 | **주택담보대출** 한도 (LTV·DSR) + 정책대출 |

부동산 플랫폼은 이 변수를 절대 계산할 수 없다. **비교표의 마지막 칸은 은행만 채울 수 있다.**

## 1-3. KB 관점: 만기 = 여신의 분기점

- 전세대출 만기 시점은 **타행 대환으로 이탈이 발생하는 순간**이자,
- 전세→매매 전환으로 **주담대(은행 최대 여신)가 새로 생기는 순간**이다.
- 이 순간을 D-90부터 잡는 서비스는 **방어(이탈 방지)와 공격(신규 여신)을 동시에** 수행한다.
- KB의 "부동산 비금융 데이터 ↔ 금융 선순환" 전략의 실행체이기도 하다.

## 2-1. 타깃: **만기를 앞둔 임차인** (D-120 ~ D-30)

나이가 아니라 **상태**로 정의된 타깃. 데드라인이 있어 전환 의지가 이미 높다.

| 페르소나 | 상황 | 기울어진 방향 | 핵심 질문 |
|---|---|---|---|
| **P1. 사회초년생** (27세, 원룸 전세) | 첫 갱신 시즌 | 갱신 vs 이사 | "5% 올려달라는데 이게 맞아?" |

## 왜 이 구조인가

| v5의 약점 | v6의 해결 |
|---|---|
| "언젠가 집" — 만성 페인, 훅이 약함 | **만기 D-90** — 데드라인 박힌 급성 결정 |
| 하루 시뮬레이션의 존재 이유가 모호 ("구경거리") | **선택지를 체감하는 도구**로 역할 확정 |
| 예산 계산 단독으론 "계산기 아니냐" | **3갈래 비교**의 한 축으로 편입 — 비교가 제품 |
| 전환 시점이 불특정 | **만기 = 여신 분기점**, 전환 시점이 구조에 내장 |

> **v5 자산 재활용률: 약 80%.** 예산 엔진·동네 필터·하루 시뮬레이션·금융 매칭·Trust Layer 전부 유지.
> **신규 개발: 갱신 시나리오 계산기(룰 1개) + 비교표 로직/화면.**

# 4. STEP 2 상세 — 세 갈래 비교 엔진 (심장)

> 원칙 유지: **숫자는 코드가, 말은 LLM이.** 세 갈래 전부 결정론적 계산.

## 4-1. 갈래 ① 눌러앉기 (갱신) — 신규 개발분

```python
def calc_renewal(lease: Lease, rules: dict) -> dict:
    """계약갱신 시나리오. 법정 룰 기반 — 예측 아님."""
    cap = rules["renewal"]["increase_cap"]          # 법정 인상률 상한 (YAML)
    new_deposit = lease.deposit * (1 + cap)         # 상한 적용 시 보증금
    gap = new_deposit - lease.deposit               # 증액분

    # 증액분을 전세대출 증액으로 커버한다면
    loan_interest_monthly = gap * rules["jeonse_rate"] / 12

    return {
        "scenario": "renewal",
        "new_deposit_cap": int(new_deposit),
        "gap": int(gap),
        "monthly_cost": int(loan_interest_monthly + lease.monthly),
        "one_time_cost": 0,
        "notes": [
            {"text": "갱신요구권 미사용 시 1회 행사 가능(법정)", "source": "rules/renewal.yaml"},
            {"text": "임대인 실거주 등 거절 사유 존재 가능 — 확인 필요", "type": "uncertainty"},
        ],
        "basis": [...],
    }
```

> ⚠️ **정직함이 곧 안전장치:** 갱신 가능 여부는 임대인 사정에 달렸으므로 "가능하다"고 단정하지 않는다. "법정 룰상 이렇게 됩니다 + 이 부분은 확인이 필요합니다" 구조. 주택임대차보호법의 갱신요구권·인상률 상한 수치는 **YAML로 외부화하고 제출 전 최신 법령 검증** (기획서 수치는 예시).

### 월세 계약의 갱신 (전월세 공통 커버)

월세는 인상률 상한이 **보증금과 월세 양쪽**에 걸리고, 보증금↔월세를 바꾸는 경우 **전월세전환율**(법정 요율)이 개입한다. 룰 하나 추가로 처리된다 — 여전히 곱셈 수준.

```python
def calc_renewal_monthly(lease: Lease, rules: dict) -> dict:
    """월세 갱신 시나리오. 인상 상한은 보증금·월세 모두 적용."""
    cap  = rules["renewal"]["increase_cap"]
    conv = rules["renewal"]["conversion_rate"]      # 전월세전환율 (법정 — YAML)

    new_deposit = lease.deposit * (1 + cap)
    new_monthly = lease.monthly * (1 + cap)

    # 참고 지표: 이 월세를 보증금으로 환산하면? (전환율 기준)
    monthly_as_deposit = new_monthly * 12 / conv    # 비교표에서 전세·매매와 같은 저울에 올리는 용도

    return {"scenario": "renewal", "new_deposit_cap": int(new_deposit),
            "new_monthly_cap": int(new_monthly),
            "monthly_cost": int(new_monthly + jeonse_interest(lease.deposit_gap, rules)),
            "monthly_as_deposit_equiv": int(monthly_as_deposit),
            "notes": [...], "basis": [...]}
```

> 💡 **월세 사용자에게 비교표가 더 강하게 꽂힌다.** "매달 80만원이 사라진다"는 감각이 이미 있어서,
> **월세 80만 vs 전세대출 이자 52만 vs 주담대 원리금 138만(일부는 원금 적립)** 구도가 전세 사용자보다 설득력이 세다.
> 청년 타깃(대회 주제)의 월세 비중이 높다는 점에서도 정합적.
>
> 월세 사용자의 "**전세로 갈아타기**"는 별도 갈래가 아니라 **갈래 ②(옮기기)의 하위 옵션**으로 처리 — 비교표를 3열로 유지해 복잡도를 막는다.

## 4-2. 갈래 ② 옮기기 (이사) — v5 동네 필터 재활용 + 전월세 버전

```python
def calc_move(lease, persona, rules) -> dict:

    candidates = find_candidates_jeonse(budget_deposit + extra, persona.prefer)
```

```python
def calc_buy(lease, persona, rules) -> dict:
```

## 4-4. 리스크 행 — 보증료 계산 (신규, 곱셈 하나)

> 비교표가 "비용"만이 아니라 **"위험과 대비"까지 같은 저울**에 올린다. 이것이 v6.1의 완성.

```python
def calc_guarantee_fee(deposit: int, rules: dict) -> dict:
    """전세보증금 반환보증 보증료 — 보증기관 공시 요율 기반 (예측 아님)."""
    rate = rules["guarantee"]["fee_rate"]        # 공시 요율 (YAML — HUG/HF/SGI)
    annual_fee = deposit * rate
    return {
        "annual_fee": int(annual_fee),
        "monthly_equiv": int(annual_fee / 12),   # ★ 월 부담 환산 → 비교표 합산
        "basis": {"source": "보증기관 공시 요율", "rate": rate,
                  "note": "가입 가능 여부·실제 요율은 주택 유형·보증기관 심사에 따름"},
    }
```

- **왜 넣는가:** "전세 이자 41만"만 보면 싸 보이지만, 반환보증까지 넣은 **실질 월 부담**은 다르다. 이 환산을 해주는 서비스가 없다 — 비교의 정직성이 한 단계 올라간다.
- **전세사기 시대의 시의성:** 월세→전세 갈아타기 경로에서 반환보증을 함께 안내하지 않는 것이 오히려 무책임하다. 금융소비자 보호(현직자 Pick 4번) 가치와 자연 연결.
- **KB 그룹 크로스셀:** 만기 한 순간에 여신(대출) + 보장(보증·보험)이 함께 걸린다 — KB는 은행이 아니라 **금융그룹**이므로 그룹 차원 시너지 스토리가 성립.
- **원칙 유지:** 보험도 "가입하세요"라고 말하지 않는다. **"이 길의 위험은 이것이고, 대비 수단의 비용은 이만큼"까지만.** 가드레일에 보험 권유 표현 차단 추가.

## 4-5. 비교표 조립 + LLM의 역할

```python
comparison = build_table([calc_renewal(...), calc_move(...), calc_buy(...)])
# LLM: 표의 숫자를 절대 만들지 않고, "이 표를 읽는 법" 내레이션만 생성
#  예: "매달 나가는 돈만 보면 눌러앉기가 가장 가볍지만,
#       2년 뒤 같은 고민을 다시 하게 돼요. 사기는 월 부담이 크지만
#       그 돈의 일부는 이자가 아니라 원금으로 쌓여요."
# 가드레일: "~하세요" 권유 표현 차단. 서술만 허용.
```

> 💡 **"틀리면 큰일" 리스크가 없는 이유:**
> ① 모든 숫자 = 공개 룰(법령·LTV·요율) × 공개 데이터(실거래) — 계산이지 판단이 아님
> ② 불확실 요소(갱신 거절 가능성, 실제 대출 심사)는 **표 안에 '확인 필요'로 명시**
> ③ 결론 문장 없음 — 세 칸을 나란히 보여줄 뿐, 고르는 건 사용자
> ④ 모든 화면에 "참고 추정치, 실제 조건은 심사·계약에 따름" 고지

# 8. 기대효과와 수익 구조

## 8-1. 전환 경로 — 세 갈래 모두 KB 상품으로 수렴

```
   눌러앉기 ──▶ 전세대출 연장·증액   (🛡 이탈 방지 — 방어)
```

| **브랜드** | "결정을 대신하지 않고, 비교를 도와주는 은행" — 영업 아닌 조력 포지션 | NPS, 공유율 |

## 8-3. 고객·사회 효과
- 갱신 통보 기한을 놓치거나 관성 갱신으로 손해 보는 일 감소
- **보증금 반환 리스크의 인지·대비 개선** — 반환보증 존재와 비용을 결정 시점에 알려줌 (전세사기 시대의 소비자 보호)
- 법정 인상률 상한 등 **임차인 권리 정보의 접근성 개선** (금융소비자 보호 — 현직자 Pick 4번 가치와도 연결)
- "월세 소진 vs 자산 형성" 비교를 통한 청년 자산 형성 지원 (ESG)

# 10. 차별성

## 10-1. 역대 수상작(1~7회) 대비

| 비교 | 차이 |
|---|---|
| 7회 임상시험 리스크 (최우수) | **같은 공식** — "결과 대기 구간의 공포"를 잡음. 그들은 임상 발표 텀, 우리는 **계약 만기 텀**. 도메인 완전 상이 |
| 6회 Kard-Toon | 상품→광고. 우리는 **결정의 순간→비교→금융** |
| 4회 전세사기 OCR | 계약 문서 위험 진단. 우리는 **만기 의사결정 비교** |
| **"만기 3갈래 비교"** | **1~7회 전체에 없음. 시중 서비스에도 없음 (부동산 앱=매물, 은행 앱=상품별 한도)** |

## 10-2. 예상 질문 방어

| 질문 | 답 |
|---|---|
| "GPT에 데이터 넣은 것 아닌가?" | 3갈래 계산은 코드(법령·규정 룰), 개인화 하루 콘텐츠는 생성 AI 고유 영역. **에이전트가 3개 계산기를 오케스트레이션**하는 구조 자체가 시연 포인트 |
| "잘못된 비교로 손해 보면?" | 판단·권유 없음(가드레일) + 전 수치 근거 표기 + 불확실 요소 명시 + "참고 추정치" 고지 |
| "은행 앱 한도조회와 뭐가 다른가?" | 한도조회는 **상품 하나의 숫자**. 우리는 **인생의 세 갈래를 같은 저울에** 올림 — 그리고 그 저울은 은행만 만들 수 있음 |
| "타겟이 좁지 않나?" | 임차 가구 수백만 × 2년 주기 = 상시 발생. '만기 임박'은 좁힘이 아니라 **타이밍 정밀화** |
