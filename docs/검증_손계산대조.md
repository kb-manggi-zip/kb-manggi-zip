## 🔴 불일치 1건 — 화면 "실질 월 부담" 보증료 이중계산

### 원인 (어느 단계·어느 값·기대 vs 실제)
- **단계**: 프론트 표시 `frontend/src/screens/CompareTable.tsx:255`
  ```tsx
  실질 월 부담: {formatMonthly(branch.monthlyBurden + branch.guaranteeMonthly)}
  ```
- **값**: `compute_compare`의 `monthlyBurden`은 **이미 보증료를 포함**한다.
  - 근거(P1 월세 이사): `monthlyBurden 93,758 = 이자 83,333 + 보증료 10,425` — 즉 보증료 이미 반영됨.
  - `guaranteeMonthly`는 그 **내역(브레이크다운)** 필드지 추가액이 아님.
- **기대 vs 실제**:
  | 케이스 | 화면 "실질"(현재) | 올바른 실질 | 과대 |
  |---|--:|--:|--:|
  | P2 이사 | 774,753 + 55,103 = **829,856** | 774,753 | +55,103 |
  | P2 갱신 | 84,400 + 32,533 = **116,933** | 84,400 | +32,533 |
  | P1 이사 | 93,758 + 10,425 = **104,183** | 93,758 | +10,425 |
  | 매매(전 케이스) | guar=0 → 이중계산 없음 | 정확 | 0 |
- 부수 문제: 같은 카드의 "월 부담 77만 **+ 보증료 6만**" 표기도 오해 유발(77만이 이미 보증료 포함).

### 왜 생겼나 (설계 의도와 코드의 어긋남)
- E2E §3-3은 "이자 41만 → 반환보증까지 넣으면 실질 45만"으로 **monthlyBurden=이자, 실질=+보증료**를 의도.
- 그러나 `compute_compare`는 **monthlyBurden=이자+보증료**(이미 실질)로 구현 → 표시단에서 또 더해 이중계산.

### 수정 — ✅ 옵션 A 적용 완료 (프론트만, 동치 무영향)
`CompareTable.tsx` 수정: `monthlyBurden`을 '실질(보증료 포함)'로 그대로 표시하고, 아래에 **분해**:
```
실질 월 부담 (반환보증료 포함)
  77만원                              ← monthlyBurden 774,753 (한 번만)
이자·월세 71.9만 + 반환보증료 5.5만 포함   ← (monthlyBurden − guaranteeMonthly) / guaranteeMonthly
```
- 이중 더하기(`monthlyBurden + guaranteeMonthly`) 제거 → 과대 표시 해소.
- `compare.py`/`compare.ts` **미변경** → 엔진 동치 테스트 영향 0. E2E §3-3("이자 싸 보이지만 실질 더 큼")과 1:1.
- (옵션 B=백엔드 의미변경은 채택 안 함 — fixtures 재생성 리스크 대비 이득 작음.)
