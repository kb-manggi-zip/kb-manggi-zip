# 근거 있는 개인화 × 통제된 에이전트 — KB 만기상담소

> 한 줄: **"AI가 똑똑해서"가 아니라 "근거·통제·기록으로 신뢰할 수 있어서"** 차별적이다.
> 이해·설명은 AI가, 계산은 규칙이, 결정은 사람이. 아래 주장은 전부 코드에 대응한다.

---

## 1. 판단을 감이 아니라 통계에서 도출한다

동네 추천의 가중치조차 임의값("감으로 0.35")이 아니다. **국토부 2024 주거실태조사 '이사 사유'
응답률**에서 계산한다.

- 직주근접 30.6% + 교통 편리 25.5% = **56.1%** → 정규화해 **통근 가중치 46%**
- 네 축 중 **통근만 원문 응답률 그대로** 쓴다(나머지는 근사, 코드에 `🔴 검증 중` 표시 — 정직하게 공개)

**점수식도 블랙박스가 아니다.** 누구나 검산할 수 있는 순수 함수다:

| 축 | 공식 | 가중치 |
|---|---|---|
| 통근 | `(60−분)/30` (30분 만점, 60분 0점) | 46% |
| 생활·소비 | `상권밀집도 × 소비성향` | 20% |
| 선호지역 | 선호 구면 1.0 | 19% |
| 예산 | 종형(여유 10% 최고점) | 15% |

**실제 계산 예시(코드 출력 그대로)** — 1인·예산 3.6억·마포 성산동:
`통근 0.133×0.528 + 예산 0.997×0.131 + 소비 1.0×0.174 + 선호 1.0×0.167 = ` **0.542**.
화면에는 근거가 함께 뜬다: *"통근 56분(가중치 52%·조사상 최우선)", "음식점·카페 237곳"*.

## 2. 에이전트는 "통제된" 개인화만 한다

사람 상황은 무한 조합이다(반려동물·학군·재택…). 규칙표는 **"반려동물"** 은 잡아도 **"마당 있는
집"** 은 놓친다 → **그래서 의미를 이해하는 에이전트(LLM)** 가 자유입력을 해석한다. 단:

- **LLM은 새 점수·새 축을 지어내지 않는다.** 정해진 **4개 축의 가중치만** 0.3~2.0배로 조정하고,
  스키마·범위를 어기면 **즉시 키워드 규칙으로 폴백**(창작 차단).
- **모순은 최종 프로필에서 AI가 전체 맥락으로 검증**한다(키 있으면 LLM 의미 검증, 없으면 규칙 기반
  간이 검증으로 대체). "재택근무 + 통근이 중요"처럼 상충하면 문진 복귀 없이 **그 자리에서 되묻고
  (인라인 해소: A/B·둘 다·가구 유형 변경), 사용자가 고른 뒤에만 반영**한다.
- **사용자가 확인 버튼을 눌러야만 반영**된다. 확정 전 신호는 `noteAdjust={}` — **어떤 계산에도 안 실린다.**
- **API 키가 없어도** 같은 규칙표로 대체돼 서비스는 안 죽는다(오프라인 완주). 데모는 키 없이도 전 기능 시연.

> 즉 "자율 계획"이 아니라 **감사 가능한 닫힌 루프**: 해석(AI) → 사용자 확정(HITL) → 결정론 계산.

## 3. 소비 데이터를 두 갈래로 쓴다 (성향 × 여력)

소비는 **성향 도출**과 **지출 여력 분석** 두 파이프라인으로 나뉜다. 같은 마이데이터를 읽되
계산·출력이 분리돼 있다.

**(A) 성향** — 증거 위계로 조립한다. **강한 증거가 약한 증거를 덮어쓰고, 출처를 항상 태그한다:**

> ① 본인이 말한 것(진술) > ② 실제 소비 기록(마이데이터) > ③ 가구 유형 평균(세그먼트)

예) 세그먼트가 "카페 성향"이라도, 개인 실측이 "카페 지출 또래의 0.6배"면 **실측이 덮어써** 그 사람의
동네 소비축 점수를 낮춘다. 통계를 개인 사실로 위장하지 않는다.

**(B) 여력** — **가드레일 걸린 Text-to-SQL**로 개인 지출을 분석한다. **질문도 결과도 개인화된다.**
- 페르소나마다 **다른 질문**을 생성한다(신혼=이사·전세 관련 / 1인 재택=관리비·구독).
- 그 SQL을 **7종 가드레일** 안에서 **실제 실행**한다: SELECT만·테이블/컬럼 화이트리스트·
  `persona_id` 슬롯 강제(타인 데이터 차단)·행 상한·실패 폴백·전 과정 trace.
  (예: P2 월별 지출 쿼리 실행 결과 `2026-05: 274만 / 06: 274만` — 표준 폴백값이 아닌 실제 쿼리 결과)
- 결과 → 리포트 ⑤: *"선택하신 '이사'의 월 부담 **77만**은 현재 변동지출 여력 **153만** 안에 있어요."*
  (신혼 P2 실행값: 이사 월부담 774,753 / 변동여력 1,529,982. 1인 P1은 여력 107만)

## 4. 환각 없는 서사 — 숫자를 원본과 자동 대조한다

"이 동네에서의 하루"는 **facts(실측 통근·상권·실거래)에 앵커된 문장**만 만든다.
- 프롬프트 제약: 가격·개수·시설 상태(노포/활기/무료) **단정 금지** — 없는 건 지어내지 않는다.
- **생성문의 모든 숫자가 facts에 있는 값의 부분집합인지 자동 검사**한다. 아니면 **재생성 2회 → 폴백**.
  (예: facts에 없는 "아메리카노 3,000원"을 생성하면 **차단**되고 안전 문장으로 대체된다.)
- **검증 수행이 trace에 남는다** — 발품 span의 `verify_numbers_grounded`·`verify_ungrounded_retries`·
  `llm_attempts` 필드로 "무엇을 대조해 통과/재생성했는지" 사후 확인 가능(관측 코드 `core/llm.py`).

---

## 5. 절제가 곧 신뢰다

과장하지 않는 것이 이 서비스의 태도다.
- **표본 5건 미만이면 전세가율을 표시하지 않는다**(근사·추정 금지).
- **소비 매칭은 식음료 축부터** 시작했다. 장보기·여가 데이터는 수집돼 있으나 **아직 점수에 반영하지
  않으며**, 반영은 로드맵이다.
- 동 단위 데이터가 없으면 **"구 기준"이라 정직하게 표기**하고 동별 차별 팩트만 카드에 남긴다.
- 실측(통근·상권)과 합성(실거래·마이데이터)을 **표로 구분해 공개**한다.

---

## 6. 전 과정을 감사할 수 있다 (관측 가능성)

분석은 **Langfuse span 트리**로 남는다: `intake → clarify → compare → route → persona → narrate`,
그리고 `profile_validation`(상충 검증)·`spend_query`(질문·SQL·폴백)·verify(숫자 대조 결과)까지.
**"왜 이 동네를 추천했나"를 사후에 재구성**할 수 있다 — 블랙박스가 아니다.

## 7. 데이터 진실성 (있는 그대로)

| 데이터 | 상태 |
|---|---|
| 통근 시간(ODsay) | ✅ 실측 스냅샷(구 단위) |
| 상권(카페·음식점) | ✅ 실측 스냅샷(소상공인 상가정보) |
| 대출/갱신/보증 규정 | ✅ 공시·법령 근거(rules/*.yaml, 확인일 기록) |
| 동네 가중치 | ✅ 국토부 주거실태조사(통근축) + 근사(나머지, 검증 중) |
| 실거래(시세) | ⚙️ 국토부 API **연동 구조 완성**(`refresh_deals.py`) · 시연은 **동별 대략 시세를 중심으로 한 정규분포 합성**(실거래 아님, 키 있으면 실데이터 교체) |
| 마이데이터(소비) | ⚙️ 합성 데모 · 실서비스는 동의 후 실 내역(로직 완성, seam만 교체) |

## 부록: 개인화 시연 시나리오 (발표용)

- **개인화가 순위를 바꾸는 시연은 P2(신혼)·매매 경로로 한다.** "재택이라 통근 덜 중요"를 확정하면
  상위 동네 순서가 실제로 바뀐다(통근 가중치↓ → 통근 먼 동네가 상승).
- 1인·이사 경로는 후보가 아직 구 단위 공통값이 많아 순위 변화가 잘 안 보이므로, **개인화 임팩트
  시연에는 쓰지 않는다**(대신 계산·발품·지출 시연에 적합).
