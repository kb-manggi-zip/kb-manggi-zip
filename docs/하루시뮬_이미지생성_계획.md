# 하루시뮬(SC-07) 씬 이미지 생성 계획

> 초안 — 팀 확인 후 실행(비용이 한 번에 나가는 배치라 사전 합의 필요)

## 뭘 만드는가

SC-07 "하루시뮬"은 지금 화면 틀만 있고 5개 시간대 씬을 Unsplash **스톡사진**으로 채운 가라 상태(갈래 3개끼리도 같은 사진 재사용, 지역 커스텀은 82개 동 중 3개뿐). 이걸 **동네마다 실제로 다른 AI 생성 이미지**로 바꾸는 계획.

## 핵심 구조 — "통근 + 그 동네가 실제로 가진 특징"

고정된 5칸에 동을 억지로 끼워맞추지 않고, **그 동이 실제로 가진 태그만 골라서** 하루로 구성한다.

- **통근** (항상 포함, 아침 자리): 초역세권 태그 있으면 역 장면, 없으면 골목길
- **그 동의 특징 태그** (있는 것만): 카페거리 / 마트·편의점 밀집 / 학원가 / 공원 인접 — 이 중 그 동이 가진 것만 표시(0~4개, 고정 아님)

각 태그는 원래 어울리는 시간대가 있어서, **있는 것만 골라 자연스러운 순서(아침→밤)로 배치**한다:

| 순서 | 카테고리 | 매칭 태그 |
|---|---|---|
| 🌅 아침 | 통근 | 초역세권(항상 포함) |
| ☕ 오전 | 카페 | 카페거리 |
| ☀️ 낮 | 공원 | 공원 인접 |
| 🌇 저녁 | 마트 | 마트·편의점 밀집 |
| 🌙 밤 | 학원가 | 학원가 |

예: 카페거리+마트만 가진 동 → 통근(아침)→카페(오전)→마트(저녁), 3씬. 태그 없는 동 → 통근만, 1씬.

> **여가시설 밀집 태그는 이미지 카테고리에서 제외.** 씬 소재로 자연스럽게 안 붙어서(집 배경에 억지로 넣는 것보다) — 태그 자체는 카드·텍스트에 계속 쓰이니 데이터가 버려지는 건 아님.

## "동마다 실제로 달라지나?" — 카테고리는 5개뿐인데

카테고리(장면 종류)는 5개로 유한하지만, **이미지는 카테고리별로 82개 동이 나눠 쓰는 게 아니라 동마다 따로 생성**한다. 같은 "카페거리" 카테고리라도:
- 동마다 별도 이미지 생성(파일 공유 안 함)
- 프롬프트에 그 동의 실제 수치(카페·음식점 356곳 vs 300곳 등)를 넣어 "북적임 정도"를 다르게 표현 가능

다만 한계는 인정한다 — 유한한 카테고리로 무한한 동네를 완전히 다르게 그릴 순 없고, 예산대가 비슷해 실제로 특징이 겹치는 동네는 이미지도 비슷하게 나올 수 있다. **이건 왜곡이 아니라 정직한 반영**(비슷한 동네를 억지로 다르게 그리면 그게 오히려 임의 작문). "이 동네가 맞다"는 확신은 이미지가 아니라 동 이름·실측 통근분·실거래가 같은 텍스트가 담당 — 이미지는 분위기만.

## 갈래·가구유형은 이미지에 안 나눔

- **갈래(이사/매매/갱신)**: 물리적 거리는 계약 형태로 안 바뀜 — 캡션(`caption1`/`caption2`)만 갈래별, 이미지는 공용.
- **가구유형**: 개인화는 이미 계산된 축 우선순위(통근/소비/예산/선호지역)로 **씬을 굳이 새로 안 만들고 순서 강조 정도만 반영** + 기존 텍스트 내레이션이 담당. 이미지 자체를 가구유형별로 나누면 비용만 3~4배.

## 스코프·비용

82개 동 × (통근 1 + 보유 태그 수) — 정확한 장수는 82개 동 태그 분포에 달림, 대략 200~300장대(기존 "고정 5×82=410"보다 적음, 태그 없는 조합은 아예 안 만드므로). 표준 요율(장당 $0.039) 기준 대략 **1.5~2만원**. 1회성 비용.

## 이미지엔 랜드마크 이름 안 넣음

"합정역"이라고 프롬프트에 넣어도 실제 합정역은 안 그려짐 — 이미지는 계속 일반화된 분위기만. **캡션(텍스트)에 실제 역·공원 이름을 넣을지는 미정**(지금 3개 동 커스텀 씬은 이미 그렇게 함). 이름 데이터(카카오 API의 `place_name`)는 사용 여부와 무관하게 지금 저장해두는 걸 추천(같은 API 호출 재사용, 나중에 다시 부르는 것보다 쌈).
