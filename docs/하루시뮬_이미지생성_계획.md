# 하루시뮬(SC-07) 씬 이미지 생성 계획

> 상태: 초안 — 팀 확인 후 실행(비용이 한 번에 나가는 오프라인 배치라 사전 합의 필요)
> 관련: `feat/gemini-connection`(API 연동 준비), `backend/data/region_enrich.yaml`(태그), `frontend/src/data/scenes.ts` / `backend/app/agents/scenes.yaml`(현재 스톡사진)

## 1. 지금 상태

`DayPlayer.tsx`(SC-07)는 완성된 화면이고, 5개 시간대 씬(🌅아침·☕오전·☀️점심·🌇저녁·🌙밤)을 넘기며 보여준다. 문제는 **이미지가 전부 Unsplash 스톡사진**이라는 것 — 확인해보니 갈래(이사/매매/갱신)끼리도 같은 URL을 그대로 재사용하고 있고(캡션 텍스트만 다름), 지역별 커스텀(`SCENES_BY_REGION`)도 82개 동 중 3개(망원·홍제·보문)뿐이며 그마저 이미지 자체는 여전히 스톡사진이다(캡션만 실제 지명 언급). **즉 지금까지 "개인화"는 100% 텍스트(캡션)였고, 이미지는 한 번도 그 동네를 반영한 적이 없다.**

## 2. 핵심 설계 질문 3가지

### Q1. 이미지가 갈래(이사/매매/갱신)별로 달라야 하나?
**아니오.** 지금도 갈래 간 이미지가 동일(캡션만 다름) — 같은 물리적 거리가 계약 형태에 따라 다르게 생기지 않으므로 새 이미지도 **동×시간대만으로 결정**하고, 갈래 차이는 지금처럼 캡션(`caption1`/`caption2`)이 전담한다. 이걸로 갈래 3배수 비용을 피한다.

### Q2. 이미지가 페르소나(가구유형: 1인/신혼/자녀 등)별로 달라야 하나?
**권장: 아니오(이미지는 공용, 개인화는 텍스트로).** 근거:
- 이미 `narrator.narrate_lifestyle()`이 가구 소비성향(`spending_profiles.yaml`)·통근·예산·실거래를 반영한 개인화 내레이션을 만들고 있음 — 이 텍스트 채널이 이미 "그 사람"을 담당.
- 이미지까지 페르소나별로 나누면 82동×5씬×페르소나 수(3~4종)로 **비용이 3~4배(약 6.6~8.8만원)**로 뜀. 반면 텍스트 개인화는 이미 공짜(기존 LLM 호출에 포함).
- 이미지에 사람이 나온다면(뒷모습) **가구유형과 무관한 중립적 묘사**(성별·연령 특정 안 함)로 통일 — "누구에게나 자연스러운 뒷모습" 한 가지면 충분하고, 굳이 페르소나마다 다른 사람을 그릴 근거가 약함(오히려 특정 이미지로 고정하면 안 맞는 페르소나에게 위화감).
- **미채택 대안(참고용)**: 정 필요하면 페르소나 전체가 아니라 "자녀 유무"만 이진 분기(유모차 유무 등)해서 2배(약 4.4만원)로 절충하는 방법도 있음 — 지금은 안 하는 걸로 하되, 팀에서 원하면 이 옵션 열어둠.

### Q3. 태그·상권 데이터를 씬에 어떻게 반영하나?
동이 가진 태그가 있으면 해당 씬에 반영, 없으면 일반(폴백) 버전 — **동마다 프롬프트가 달라짐(개인화의 실체)**.

| 씬 | 시간대 | 매칭 태그 | 있을 때 | 없을 때(폴백) |
|---|---|---|---|---|
| 🌅 아침 | 출근길 | 초역세권 | 지하철역 입구 장면 | 골목길 걷는 장면 |
| ☕ 오전 | 카페 | 카페거리 | 카페 밀집 거리 | 카페 한 곳 |
| ☀️ 점심 | 식사/공원 | 공원 인접 | 공원 장면 | 일반 식당가 |
| 🌇 저녁 | 퇴근·장보기 | 마트·편의점 밀집 | 시장/마트 거리 | 저녁 골목 |
| 🌙 밤 | 집 | 학원가·여가시설 밀집(배경 텍스처만) | 학원 불빛 거리 / 체육시설 야경 | 일반 주거지 |

한 동이 여러 태그를 가지면(예: 초역세권+카페거리+공원인접) 5개 씬 중 해당하는 자리에만 반영, 나머지는 폴백.

## 3. 최종 스코프

**82개 동 × 5씬 = 410장.** 갈래·페르소나 무관 공용(위 Q1·Q2 결론). 태그 없는 동(19개)은 전부 폴백 버전이라 사실상 "동 이름만 다른" 유사 이미지가 되지만, 폴백도 나름 톤(예산대 등)은 유지 가능.

## 4. 프롬프트 템플릿

```
Photorealistic photo, {lighting}, {scene_visual}, in a Seoul residential/commercial
neighborhood street. A person is seen from behind, {activity}, no visible face,
neutral clothing (household-agnostic). Low-rise Korean buildings, natural everyday
atmosphere, DSLR photo quality, no text, no logos, no specific real signage.
```

| 변수 | 값 출처 | 예시 |
|---|---|---|
| `lighting` | 시간대 고정값(5개) | "early morning warm sunlight" / "midday bright sunlight" / "golden hour evening light" / "warm night streetlights" |
| `scene_visual` | 위 §2 Q3 매핑표(태그 있으면 구체적, 없으면 일반) | "a subway station entrance with morning commuters" |
| `activity` | 씬 고정값(5개, 갈래·페르소나 무관) | "walking toward the station" / "holding a coffee cup" / "sitting on a park bench" / "carrying a grocery bag" / "walking home" |

`region_name`(동 이름)은 **프롬프트에 직접 넣지 않는다** — 실제로 그 동을 정확히 그리는 게 아니라 "그런 느낌"을 만드는 것뿐이라, 지명을 넣으면 사실과 다른 특정 장소를 그렸다고 오해할 수 있음(L1 원칙: 실제 랜드마크 명칭 단정 금지, 지금 캡션 규칙과 동일).

## 5. 실행 계획

1. `scripts/generate_scene_images.py` 신규 작성 — `region_enrich.yaml`(82동 tags) 순회 → 동×5씬 프롬프트 조립 → Gemini 호출 → `backend/data/scene_images/{region_id}_{scene_idx}.png` 저장
2. 저장된 경로를 `backend/app/agents/scenes.yaml` + `frontend/src/data/scenes.ts`의 `visual` 필드에 채워 넣기(스키마 변경 없음, 값만 교체)
3. 갈래별 캡션(`caption1`/`caption2`)은 기존 방식 유지(그대로 둠)
4. 실패/재시도 로깅(refresh 스크립트들과 동일 패턴 — 실패해도 조용히 안 넘어가고 로그 남김)
