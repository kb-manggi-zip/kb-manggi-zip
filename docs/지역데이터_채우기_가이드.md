# 지역 대표 데이터 채우기 가이드 (팀원용)

> **하루 '온라인 발품' 내레이션**을 더 구체적·정확하게 만들기 위해 동네별 대표 정보를 채우는 작업.
> 코드는 이미 뚫려 있음 — **`backend/data/region_facts.yaml` 값만 채우면** 자동 반영된다(코드 수정 0).

## 30초 요약 (자동 + 수기 2트랙)
- **🤖 자동(상권)**: `grocery`·`dining_cafe`·`leisure` = **소상공인 상권 API로 자동 집계**. `.env`에 `SBIZ_API_KEY`(Decoding 키) 넣고 `TRADES_DB=data/trades.demo.db python scripts/refresh/refresh_regions.py` → trades_store.region_facts에 저장. (반경 500m 업소 수)
- **✍️ 수기**: `transport`·`price_level`·`notes` = `backend/data/region_facts.yaml` 의 `facts:` 아래 직접(경로·물가는 API 자동화 어려움).
- **반영**: `narrator`가 DB(자동) + YAML(수기) 병합 → 발품 프롬프트에 주입. 둘 다 없으면 이름+태그 폴백.
- **원칙**: **임의 작문 금지.** 자동은 API, 수기는 카카오맵·ODsay 등 확인 가능한 것만.

## 채울 대상 (regionId = 프론트 `Region.id`)
| 갈래 | regionId | 동네 |
|---|---|---|
| 매매 | `mapo` / `eunpyeong` / `dobong` | 합정동 / 녹번동 / 창동 |
| 전세 | `seongbuk` / `nowon` / `jungnang` | 길음동 / 상계동 / 면목동 |
| 월세 | `mapo-m` / `seodaemun-m` / `seongbuk-m` | 망원동 / 홍제동 / 보문동 |

`mapo-m`(망원동)은 **예시로 채워져 있음** — 그 형태 그대로 나머지 8개를 채우면 된다.

## 각 필드 스키마 & 출처
```yaml
facts:
  <regionId>:
    name: "구 동"                      # 한글, 표시 확인용
    transport: ["6호선 망원역 도보 6분", "시청까지 약 28분"]   # 출처: 카카오맵 길찾기 / ODsay
    grocery:   ["망원시장 도보권", "대형마트 차량 10분"]        # 출처: 카카오맵 '마트/시장'
    dining_cafe: ["망리단길 카페 밀집", "먹자골목"]             # 출처: 카카오맵 상권
    leisure:   ["한강공원 자전거 5분"]                          # 출처: 카카오맵 '공원/하천'
    price_level: "중"                  # 저|중|고 (선택) — 참가격/체감, 근거 있으면
    notes: "젊은층 많고 야간 활기"      # 한 줄 분위기 (선택)
```
- 리스트 항목은 **1~3개**면 충분. 문장형("~ 도보 N분")으로.
- 소요시간·거리는 **대략치**로 ("약 N분"). 정밀 수치 강요 안 함 — 발품은 정성적 서술이라 대략이면 됨.
- 모르면 **비워둠**(빈 리스트/생략 OK). 빈 필드는 프롬프트에서 자동 제외된다.

## 하면 안 되는 것
- ❌ 확인 안 한 가게 이름·가격 지어내기 (예: "OO카페 아메리카노 2,500원").
- ❌ `regionId` 오타 (프론트 `frontend/src/data/regions.ts`의 `id`와 정확히 일치해야 함).
- ❌ 금융 숫자(한도·월부담 등) 여기 넣기 — 그건 `rules/*.yaml`·compare 담당. 여긴 **생활 정보만**.

## 확인 방법 (채운 뒤)
```bash
cd backend && source .venv/bin/activate
# LLM 켜서 실제 발품 문장 확인(키 필요):
LLM_ENABLED=true python -c "
from app.agents import narrator
print(narrator.narrate_lifestyle({'region':{'id':'seodaemun-m','name':'서대문구 홍제동','tags':[]}, 'finance':{'household':'청년'}, 'branch':'이사'}))
"
# LLM 없이 구조만:  python -c "from app.agents import narrator; print(narrator._facts_block('mapo-m'))"
pytest -q   # 깨지는 것 없나
```

## Done 기준
- 9개 regionId 각각 `transport`·`grocery`·`dining_cafe` 최소 1개씩 채움 (leisure·price_level·notes 선택).
- 각 항목 **출처 확인**(카카오맵/ODsay 등). 임의 작문 0.
- `pytest` 통과 + 발품 문장에 그 동네 특징이 실제로 반영되는지 눈으로 확인.

## (참고) 나중에 실 API로 자동화하려면
지금은 수기 YAML. 향후 `narrator._region_facts()`를 카카오/ODsay/참가격 API 호출(+`@cached`)로 교체하면 자동 수집 가능. 스키마(`facts[regionId]`)만 유지하면 narrator·프론트 무수정.
